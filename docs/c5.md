# C5: índice Redis original

Corrección limitada a C5. Las persistencias PostgreSQL/Redis de journeys,
telemetría, comandos, ACK, eventos y riesgo se mantienen.

## Referencia encontrada en Git

Commit `a2fbac3`, anterior a `7da9a4b`:

- `scripts/c5_redis.py` consultaba la capa `c5_camaras_videovigilancia` de Mapoteca,
  guardaba los IDs de origen (`id_unico`, `id` o `id_camara`), posiciones GEO y
  hashes con id, direccion, esquina, colonia, alcaldia, poste, boton, altavoz,
  lat y lon. Usaba localhost:6379, DB 5, `acompanamiento:cdmx:c5`, `meta:camara:{id}`.
- `MotorTelemetria` consultaba ese mismo Redis mediante GEORADIUS y HGETALL.
- `GeoC5Service` tenía una discrepancia: localhost:6380, DB 0. Usaba GEOSEARCH
  con radio/límite, pero solo devolvía el primer resultado sin metadata.
- No se encontró `app/api/c5_cameras.py` antes del último cambio. Se conserva la
  ruta actual `/api/c5/nearest` y se conecta al almacenamiento original.

El servicio C5 ahora sigue la DB/clave del cargador original y de MotorTelemetria.
No se importan nuevos datos. El cargador histórico queda disponible en Git;
`scripts/c5_redis.py` es ahora una herramienta de consulta de solo lectura.

## Configuración y contrato

En `backend/.env`, independiente de `REDIS_URL` para journeys/comandos/riesgo:

```dotenv
C5_REDIS_URL=redis://localhost:6379/5
```

Se consultan exclusivamente:

```text
acompanamiento:cdmx:c5       GEOSET existente
meta:camara:{id}            HASH existente
```

```http
GET /api/c5/nearest?latitude=19.483051&longitude=-99.073564&radius_m=1000&limit=5
```

Las coordenadas anteriores pertenecen al hash CAM-08705 compartido por el usuario,
no son una captura del teléfono ni un registro insertado durante esta corrección.

- `latitude` y `longitude` son obligatorias; `radius_m` conserva su valor por
  defecto de 1,000 m (máximo 50,000); `limit` permite entre 1 y 100, por defecto 10.
- `results` contiene hasta `limit` elementos ordenados por distancia ascendente.
  Cada elemento conserva los campos existentes del hash y agrega `distance_m`,
  `latitude` y `longitude` obtenidos de `lat`/`lon` o de la posición GEO existente.
- Los IDs se toman directamente del GEOSET; no se generan, renombran ni reemplazan.
  No se añaden NULL, N/A ni valores de WiFi para llenar campos ausentes.
- Se conservan `encontrado`, `id_poste`, `distancia_metros` y `metadata` del primer
  resultado para compatibilidad con `MotorTelemetria`.
- GEOSEARCH utiliza ASC, COUNT, WITHDIST y WITHCOORD. Si Redis no conoce GEOSEARCH,
  se usa el GEORADIUS original con los mismos parámetros. Los hashes se leen con
  HGETALL. No hay escrituras, reconstrucciones ni llamadas PostgreSQL en C5.
- Redis C5 no disponible devuelve HTTP 503. Un índice accesible sin coincidencias
  devuelve HTTP 200 con `encontrado: false` y `results: []`.

Consulta de solo lectura desde PowerShell, raíz del proyecto:

```powershell
.\backend\.venv\Scripts\python.exe scripts\c5_redis.py --latitude 19.483051 --longitude -99.073564 --radius-m 1000 --limit 5
```

## Pruebas de esta corrección

`tests/test_c5.py`: **7 aprobadas, 1 omitida**.

- Conversión sin mutación de lat/lon del hash real compartido por el usuario.
- Petición al endpoint bloqueando explícitamente toda conexión SQLAlchemy:
  ninguna consulta PostgreSQL; respuesta real HTTP 503 por Redis inaccesible.
- Validación de coordenadas, radio y límite inválidos: HTTP 422.
- Prueba de catálogo, cantidad, CAM-*, metadata, orden y distancia: **omitida**,
  porque localhost:6379/5 no respondió. No se sustituyó con un catálogo ficticio.

Respuesta efectivamente observada para la consulta de CAM-08705:

```json
{"detail":"Redis C5 no disponible. Verifica C5_REDIS_URL."}
```

distancias con Haversine (tolerancia 0.1% o 1 m por radio terrestre/cuantización).
